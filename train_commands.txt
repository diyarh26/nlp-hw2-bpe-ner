Current staged tokenizers use per-tokenizer vocab choices selected in Phase 3.
The unedited generator accepts one `--vocab_size` per run, so tok1 and tok2
are reproduced by separate generator runs and then copied into
`trained_tokenizers/`.

Default train-file mapping used by `generate_tokenizers.py`:
tokenizer_1.pkl: domain_1_train.txt
tokenizer_2.pkl: domain_2_train.txt
tokenizer_3.pkl: domain_1_train.txt domain_2_train.txt

Selected tokenizer commands:

tokenizer_1.pkl (Twitter/domain 1) - FINAL: the domain-1-HEAVY (2:1 d1:d2) mix @
vocab 5500 (recipe-2 sweep). This beats the prior 1:1-mix @ 6000 on ALL three
competition axes: Twitter dev F1 0.4817 vs 0.4780, while tying efficiency
(0.3063 vs 0.3067 tokens/char) and tokenization speed. The 2:1 mix keeps more
Twitter coverage than the 1:1 mix while retaining the news-data regularization
that makes any mix beat domain-1-only (pure-domain-1 candidates scored <=0.4352
F1, and larger vocab hurt Twitter F1). First build the 2:1 mix with make_mix.py
(--d1_ratio 2.0 = round(2 * domain-2 line count) deterministically-sampled
domain-1 lines + all of domain 2, exact-line deduped; byte-reproducible, see
output_sha256 in tuning/results/mix_d1x2_manifest.json), then put it in tok1's
slot via --train_files_1 and take tokenizer_1.pkl.
py -m uv run python code/make_mix.py --seed 42 --d1_ratio 2.0 --domain1 data/domain_1_train.txt --domain2 data/domain_2_train.txt --output data/mix_d1x2_d2all_seed42.txt --manifest tuning/results/mix_d1x2_manifest.json
py -m uv run python generate_tokenizers.py --vocab_size 5500 --seed 42 --output_dir tuning/_stage_tok1 --train_files_1 mix_d1x2_d2all_seed42.txt
copy tuning/_stage_tok1/tokenizer_1.pkl trained_tokenizers/tokenizer_1.pkl

tokenizer_2.pkl (news/domain 2, FINAL selected vocab 12000):
Post-submission equal-axis recipe sweep re-ranked candidates by F1, efficiency
(tokens/char), and cold chars/sec. Vocab 12000 beat the old 16000 overall:
F1 0.9606 vs 0.9557 and slightly faster, with only ~5% more tokens/char.
py -m uv run python generate_tokenizers.py --vocab_size 12000 --seed 42 --output_dir tuning/_cmp/12000
copy tuning/_cmp/12000/tokenizer_2.pkl trained_tokenizers/tokenizer_2.pkl

tokenizer_3.pkl: SUPERSEDED by the Phase 4 hidden-domain recipe below (it is NO
longer the naive both-domains vocab-8000 baseline). See "Phase 4 SELECTED tok3".

Phase 4 tokenizer 3 (hidden-domain generalization) - mix recipe (GEN-01/D-01/D-02):
Build the balanced, exact-line-deduped domain-1+2 training mix: all of domain 2
plus a deterministic same-count SHA-256 sample of domain 1, deduped AFTER mixing.
Deterministic and byte-identical across runs (see output_sha256 in
tuning/results/tok3_mix_manifest.json). The ~45MB mix is a regenerable,
gitignored artifact under data/.
py -m uv run python code/make_tok3_mix.py --seed 42 --domain1 data/domain_1_train.txt --domain2 data/domain_2_train.txt --output data/tok3_mix_d1sample_d2all_seed42.txt --manifest tuning/results/tok3_mix_manifest.json
Tok3 candidate generation (04-02 + post-submission recipe sweep) - unedited generator on the mix, vocab sweep:
py -m uv run python generate_tokenizers.py --vocab_size 4000 --seed 42 --output_dir tuning/_tok3_gen/4000 --train_files_3 tok3_mix_d1sample_d2all_seed42.txt
py -m uv run python generate_tokenizers.py --vocab_size 6000 --seed 42 --output_dir tuning/_tok3_gen/6000 --train_files_3 tok3_mix_d1sample_d2all_seed42.txt
py -m uv run python generate_tokenizers.py --vocab_size 8000 --seed 42 --output_dir tuning/_tok3_gen/8000 --train_files_3 tok3_mix_d1sample_d2all_seed42.txt
py -m uv run python generate_tokenizers.py --vocab_size 16000 --seed 42 --output_dir tuning/_tok3_gen/16000 --train_files_3 tok3_mix_d1sample_d2all_seed42.txt
(then copy each tuning/_tok3_gen/{V}/tokenizer_3.pkl -> tuning/tokenizers/tokenizer_3_vocab{V}.pkl)
FINAL SELECTED tok3: vocab 6000 on the balanced mix. A later equal-axis recipe
sweep found that 6000 beats the old 8000 under the competition tradeoff:
domain1/domain2 F1 = 0.4780/0.9621 vs 0.4217/0.9587, faster cold encode, with a
modest efficiency cost. Reproduce (after the make_tok3_mix command above):
py -m uv run python generate_tokenizers.py --vocab_size 6000 --seed 42 --output_dir tuning/_tok3_cmp/selected --train_files_3 tok3_mix_d1sample_d2all_seed42.txt
copy tuning/_tok3_cmp/selected/tokenizer_3.pkl trained_tokenizers/tokenizer_3.pkl

Training method (Phase 2): the uncapped weighted word-chunk BPE trainer with
incremental local pair-count deltas and an inverted pair->chunks index. No
TRAIN_TEXT_LIMIT or training-data cap is used; the full corpora are trained
(domain_1 ~95MB, domain_2 ~29MB, tokenizer_3 on both). Training is deterministic
(no RNG), so repeated runs produce byte-identical tokenizer_{1,2,3}.pkl.
