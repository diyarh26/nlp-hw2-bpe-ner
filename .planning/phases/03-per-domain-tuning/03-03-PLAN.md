<objective>
Select per-domain tok1/tok2 vocab sizes from the VM F1 and CPU efficiency
evidence, then stage the already-measured candidate pickles as the shipped
domain tokenizers while preserving the Phase 2 tok3 baseline.
</objective>

<must_haves>
<truths>
- Selection uses the approved knee rule: within `0.02` F1 of the best candidate
  per domain, then lower tokens/char, then higher tokens/sec.
- Final tok1/tok2 must be copied from the exact candidate pickles measured in
  03-01 and evaluated in 03-02.
- The shipped tok1/tok2 files must be byte-identical to a fresh
  `generate_tokenizers.py --vocab_size {chosen} --seed 42` run for each chosen
  vocab.
- Tok3 remains the current Phase 2 vocab-8000 baseline. If
  `trained_tokenizers/tokenizer_3.pkl` is missing, regenerate to a temp
  directory with vocab 8000 and copy only `tokenizer_3.pkl`.
- `train_commands.txt` must include the per-tokenizer generator commands needed
  to reproduce staged tok1 and tok2.
</truths>
<prohibitions>
- Do not edit the four forbidden files:
  `code/base_tokenizer.py`, `code/train_ner_model.py`,
  `generate_tokenizers.py`, `check_submission.py`.
- Do not retrain chosen tok1/tok2 with a tuning-specific code path.
- Do not overwrite staged tok1/tok2 when regenerating tok3.
- Do not select a candidate that failed Phase 1 gates, reconstruction, loading,
  or encode equality checks.
- Do not run Phase 5 full F1/freeze work in this plan.
</prohibitions>
</must_haves>

<read_first>

- `tuning/results/vm_f1_results.csv`
- `.planning/phases/03-per-domain-tuning/03-CONTEXT.md`
</read_first>
<action>
Create a selection table that joins each candidate's CPU metrics with its VM F1
row by tokenizer index and vocab size.
</action>
<verify>
- Every VM row has a matching CPU row.
- Every candidate path in the joined table exists and loads.
- Any incomplete VM sweep caused by the 10h stop-rule is called out before
  selection.
</verify>
<acceptance_criteria>
- Selection is based on a complete and auditable evidence table for every
  candidate under consideration.
</acceptance_criteria>
</task>

<task id="2" title="Select per-domain vocabularies">
<read_first>
- The joined evidence table from Task 1.
- `code/bpe_tokenizer.py`
- `code/align_check.py`
- `code/speed_check.py`
</read_first>
<action>
For each domain independently:

1. Identify the best dev F1.
2. Keep candidates within `0.02` F1 of that best value.
3. Choose the lowest tokens/char among that set.
4. Break any remaining tie by higher tokens/sec.
5. Inspect/record that the choice does not obviously over-merge across entity
   boundaries compared with the neighboring vocab sizes.
</action>
<verify>
- The selected tok1/tok2 vocab sizes can be derived mechanically from the
  recorded F1, tokens/char, and tokens/sec values.
- The decision notes include any entity-boundary concerns or confirm none were
  observed.
</verify>
<acceptance_criteria>
- One selected vocab size exists for tok1 and one for tok2.
- The selected candidates are justified by the approved knee rule and
  qualitative boundary check.
</acceptance_criteria>
</task>

<task id="3" title="Stage selected tokenizers and preserve tok3">
<read_first>
- `generate_tokenizers.py`
- `train_commands.txt`
- `tuning/tokenizers/`
- `trained_tokenizers/`
</read_first>
<action>
Copy the selected candidate files into the submission tokenizer directory:

```text
tuning/tokenizers/tokenizer_1_vocab{chosen1}.pkl -> trained_tokenizers/tokenizer_1.pkl
tuning/tokenizers/tokenizer_2_vocab{chosen2}.pkl -> trained_tokenizers/tokenizer_2.pkl
```

Keep the current Phase 2 `trained_tokenizers/tokenizer_3.pkl`. If it is
missing, run:

```powershell
py -m uv run python generate_tokenizers.py --vocab_size 8000 --seed 42 --output_dir tuning/_tok3_restore
```

Then copy only `tuning/_tok3_restore/tokenizer_3.pkl` to
`trained_tokenizers/tokenizer_3.pkl`; never overwrite the staged tok1/tok2
during tok3 restoration.
</action>
<verify>
For each staged tok1/tok2, run a fresh generator comparison for the chosen vocab:

```powershell
py -m uv run python generate_tokenizers.py --vocab_size {chosen} --seed 42 --output_dir tuning/_cmp/{chosen}
fc /b trained_tokenizers\tokenizer_{i}.pkl tuning\_cmp\{chosen}\tokenizer_{i}.pkl
```

Also load all three `trained_tokenizers/tokenizer_{1,2,3}.pkl` with
`BaseTokenizer.load`.
</verify>
<acceptance_criteria>
- Staged tok1 and tok2 are byte-identical to fresh generator output for their
  selected vocab sizes.
- Tok3 is present and remains the Phase 2 baseline.
- All three shipped tokenizer files load successfully.
</acceptance_criteria>
</task>
