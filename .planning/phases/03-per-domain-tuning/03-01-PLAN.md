<objective>
Produce deterministic tok1/tok2 candidate pickles from the unedited submission
generator, then measure their CPU-local tokenizer efficiency and speed on the
matching dev text without spending VM/NER budget.
</objective>

<must_haves>
<truths>
- This project is a from-scratch BPE tokenizer for NER, not retrieval/ranking.
- Candidate pickle fidelity matters: F1 must be measured on the same byte stream
  that can later be staged for submission.
- `generate_tokenizers.py` accepts one `--vocab_size` for all three tokenizers,
  so per-domain candidates must be copied out of separate generator runs.
- The approved vocab grid is `[4000, 8000, 16000]` for tok1 and tok2.
- The CPU sweep measures dev text only:
  `data/domain_1_dev.txt` for tok1 and `data/domain_2_dev.txt` for tok2.
</truths>
<prohibitions>
- Do not edit the four forbidden files:
  `code/base_tokenizer.py`, `code/train_ner_model.py`,
  `generate_tokenizers.py`, `check_submission.py`.
- Do not train candidate pickles inside `code/tune_tokenizers.py`.
- Do not clobber `trained_tokenizers/`; Phase 2 submission tokenizers stay in
  place during tuning.
- Do not run NER locally and do not spend VM budget in this plan.
- Do not add dependencies outside the locked stack: numpy, regex, torch, tqdm.
</prohibitions>
</must_haves>

<tasks>
<task id="1" title="Generate candidate pickles via the locked generator">
<read_first>
- `generate_tokenizers.py`
- `code/bpe_tokenizer.py`
- `code/base_tokenizer.py`
- `.planning/phases/03-per-domain-tuning/03-CONTEXT.md`
</read_first>
<action>
For each `V` in `4000`, `8000`, `16000`, run:

```powershell
py -m uv run python generate_tokenizers.py --vocab_size V --seed 42 --output_dir tuning/_gen/V
```

Then copy:

```text
tuning/_gen/V/tokenizer_1.pkl -> tuning/tokenizers/tokenizer_1_vocabV.pkl
tuning/_gen/V/tokenizer_2.pkl -> tuning/tokenizers/tokenizer_2_vocabV.pkl
```

Discard that run's `tokenizer_3.pkl` for Phase 3 tuning. Keep
`trained_tokenizers/` untouched.
</action>
<verify>
- All six copied files exist under `tuning/tokenizers/`.
- Every copied file loads with `BaseTokenizer.load`.
- No files under `trained_tokenizers/` were overwritten.
</verify>
<acceptance_criteria>
- Six candidate pickles exist, covering two domains times three vocab sizes.
- Each candidate is generated by the unedited `generate_tokenizers.py` path.
- Candidate loading succeeds before any measurement or VM planning proceeds.
</acceptance_criteria>
</task>

<task id="2" title="Add measure-only CPU sweep harness">
<read_first>
- `code/test_tokenizer.py`
- `code/bpe_tokenizer.py`
- `code/base_tokenizer.py`
</read_first>
<action>
Create `code/tune_tokenizers.py` as a measure-only harness that:

- accepts the vocab grid, candidate directory, output CSV path, repeat count, and
  reconstruction sample count as CLI arguments;
- loads `tuning/tokenizers/tokenizer_1_vocabV.pkl` and
  `tuning/tokenizers/tokenizer_2_vocabV.pkl` with `BaseTokenizer.load`;
- reuses the helper behavior from `code/test_tokenizer.py` to measure
  tokens/char, tokens/sec, encode seconds, total dev tokens, and reconstruction
  rate;
- writes one deterministic row per candidate to
  `tuning/results/cpu_sweep.csv`.
</action>
<verify>
Run:

```powershell
py -m uv run python code\tune_tokenizers.py --vocab_sizes 4000 8000 16000 --candidate_dir tuning\tokenizers --results_csv tuning\results\cpu_sweep.csv
```

Then confirm:

- `tuning/results/cpu_sweep.csv` exists.
- The CSV has exactly six data rows.
- Each row has a non-empty path, positive tokens/char, positive tokens/sec,
  positive dev token count, and reconstruction rate `1.0`.
</verify>
<acceptance_criteria>
- The harness never trains tokenizers and only loads generated candidates.
- The sweep table is deterministic for fixed candidate pickles and CLI options.
- The table gives enough CPU evidence to combine with VM F1 in 03-03.
</acceptance_criteria>
</task>
