<objective>
Define the VM-only F1 sweep for the six generated tok1/tok2 candidates while
protecting the 10h Tesla M60 budget. This plan writes the runbook locally; the
actual NER runs happen only on the VM.
</objective>

<must_haves>
<truths>
- NER F1 is the final selection signal, but BiLSTM training is impractical to
  sweep locally on CPU.
- Candidate pickles come from 03-01 and must be the exact files evaluated on the
  VM.
- The approved grid is six runs: tok1 and tok2 for vocab sizes 4000, 8000, and
  16000.
- The VM budget is 10h on the Tesla M60 and is treated as hard.
- The first VM command must run `tok1@8000` alone and record wall-time before
  launching the remaining five runs.
</truths>
<prohibitions>
- Do not edit `code/train_ner_model.py`.
- Do not run VM/NER jobs locally.
- Do not expand the grid without explicit approval.
- Do not continue launching runs if the first timed run implies the six-run
  sweep will exceed the 10h budget.
</prohibitions>
</must_haves>

<read_first>

<action>
On the Tesla M60 VM only:

1. Run the tok1 vocab 8000 command first and record wall-time.
2. If projected total time for six runs fits under 10h with margin, run the
   remaining five commands.

   `tuning/results/vm_f1_results.csv`.
</action>
<verify>
- `tuning/results/vm_f1_results.csv` has six rows only if the budget stop-rule
  permits all six runs.
- Every row has domain, tokenizer index, vocab size, tokenizer path, train file,
  dev file, F1, wall-time, and log path.
- Logs exist for every recorded row.
</verify>
<acceptance_criteria>
- F1 results are collected on the VM for the exact candidate pickles generated
  in 03-01.
- Any budget stop is documented with the timed first-run evidence.
- No local CPU NER sweep is substituted for the VM results.
</acceptance_criteria>
